# 主数据巡检（mdm-sentinel）· CONTEXT

> 周期性扫描主数据相关记录、用**确定性规则**找出疑似异常 SKU、产出供 Sourcing 人工核验的报告。
> 触发 case：扎带 EL00556 的价格记录按"包"录入（一包 250 根价 14.2），却被当成"按 PCS"使用，单价被放大约 250 倍 → 7500 PCS × 14.2 = 10.6 万的错误采购单（NPO260620001），供应商打电话才发现下错单。
>
> 底座挂在 in3-cli（`sdk/poc/mdm_sentinel.py`），复用 `in3_client` SDK 的登录/凭证/分页/坑层下沉。

---

## 核心反框定（这一节最重要，先读）

**这不是"比单位字段"的主数据审计，而是"价格合理性"的异常检测。**

田野在事故复盘里已经亲手证伪了"比单位字段"这条路：

> "看不出来的……价格记录上单位的系统数据是**一致的**，是**业务意义**不一致。"

即：价格记录的单位字段写 `PCS`，物料主数据的单位字段也写 `PCS`，**字段层面完全一致**——拿 SQL 跑 `where master.unit != price.unit` 会捞回 **0 条**。真正错的是**录进去的价格数值口径**（"按包"的 14.2 被当成"按 PCS"用）。

因此唯一可用的判别信号是**价格是否合理**（朱政转向后的命题，AI 实跑找到的是"10 倍价差"）。本功能本质 = **采购单价异常检测**，根因猜测为单位/包装口径错配；输出是**给人核验的候选清单**，不是自动改数。

## 术语表（domain glossary）

| 术语 | 含义 |
|---|---|
| **主数据巡检 (mdm-sentinel)** | 周期性、规则驱动的疑似异常 SKU 发现机制。是**框架**：全量物料快照为共享底物，规则可插。本期只实现 rule #1。 |
| **单价异常 (unit-price anomaly)** = rule #1 | 某料采购单价相对其合理基线显著偏离（以虚高为主）。 |
| **包装单位错配 / PCS 异常** | 单价异常的头号根因：价格记录数值按"包"录（如一包 250 根价 14.2），却按"PCS（单根）"使用，单价被放大 ≈ 包装规格倍。**注意：价格记录单位字段与主数据单位字段都是 PCS、系统层一致；错的是数值口径，业务意义不一致。** |
| **价格记录 (price record)** | IN3 `mm.info_record`，供应商×物料×工厂的标准报价。**是朱政要 Sourcing"统一更新"的对象。** |
| **基线 (baseline)** | 某料"合理单价"的参照 = 该料 **PO 行项历史单价的中位数**（线上 PO 数据逐位验证过，最可靠）。 |
| **Gate 采购单位=PCS** | 排查域门槛：候选必须采购单位为 PCS（田野 R001）。 |
| **信号 C 包装规格抽取（命门）** | 从物料名称/描述正则抠出"N〔单位〕/包"（`250根/包`、`1000个/包`）。**单位词表必须全：根/个/只/条/片/卷/米/对/套/双/字…**——田野全表只抠出干净数值 5/3580（"个/包"能抠、扎带"根/包"漏抠），R002/R006 大分规则因此打不出来。抠到数值→高分(田野 R002=20)；只抠到包装单位无数值→低分(R003=8)。**它同时是信号 Q 整除判断和 high 确诊的前置。** |
| **信号 Q 数量模式（co-primary，田野核心）** | PO 行**采购数量**（in3_client 已有，等价替代田野手导的入库明细）：大额(≥7500/≥10000/≥50000 逐级，R004=8-12) + 整百整千占比高(R005=5) + 可被包装规格整除/折算 PCS 极大(R006=6-19)。扎带 7500/250=30 整除即此族。 |
| **信号 P 价格离散（co-primary，非辅助）** | info-record 跨供应商 最高/最低未税单价倍数 ≥ 阈值。例：EL00505 0.033 vs 473 ≈ 14343 倍；扎带 EL00556 0.0568 vs 14.2 = 250 倍。**纠田野**：他 R007 只给价格差异 3-5 分当"辅助"，结果漏了扎带——价格离散与数量模式**互补、须并列为主触发**（EL00556 价格逮/数量没逮，EL00501 价差1.27没逮/数量+包装逮，正好两个互补盲区）。 |
| **信号 D 辅材绝对值（排序）** | 辅材类目（电气辅材等）+ 单 PCS 价偏高 → 排序加权，**不单独触发**（朱政："出问题的估计都是辅材这类小东西"）。 |
| **shortlist（候选清单）** | 确定性脚本算完输出的几十条疑似 SKU。喂给 AI 判读，**不把原始数据喂进上下文**。 |
| **applies_to（规则适用谓词）** | 框架里每条规则声明自己适用的物料子集。rule #1 的 applies_to = 有 ≥1 条价格信号的料；无价格数据的料对 rule #1 是"空检/自动通过"。 |
| **抑制 (suppression)** | 已核验为误报/已修的料下次不再报。**v1 不做**（见"已知局限"）。 |

## 已锁定的设计决策（grill 结论，2026-06-24）

1. **形态：主数据质量巡检框架**（rule registry + scorer + report），单价异常注册为 rule #1。框架先行，规则各自 `applies_to`，共享**全量物料快照**（给"缺价格记录/缺采购单位"等完整性类规则留位）。
2. **rule #1 信号栈（经田野 Excel 校准，2026-06-24 修正权重）**：`Gate(采购单位=PCS) → 加权评分[C 包装规格(命门) + Q 数量模式(co-primary) + P 价格离散(co-primary) + D 辅材排序] → 分级`。**关键修正**：原设计"价格离散 B 主触发 / 包装规格 C 确诊"被真实数据推翻——主力是 C(描述包装规格)+Q(数量模式)，P(价格离散)与 Q **并列为主**而非辅助。详见下"Ground-truth 校准"。
3. **数据源**：价格 = info-record 价格记录（跨供应商最低/最高未税单价，线上 8564 条全有价、可靠）；数量 = PO 行采购数量（in3_client 已有，替代田野手导的 WM 入库明细——wm 模块当前无入库明细实体）；包装规格 = `md.material` 物料名称/描述正则。被审对象 = ① info-record 价格记录(要修的) + ② PO 行（真出事的单）。
4. **范围：全量物料快照**；rule #1 往下过滤到"有价格信号"的料。
5. **运行时：客户端定时任务**（Claude Desktop / Codex 这类带调度的 agent 客户端）→ 提示词 + 该脚本 → `execute_code` 跑 → 产出 HTML 报告。**不走** MO8/gateway 服务端 cron。
6. **算/判分层（见 ADR-0001）**：确定性脚本算 A/B/C/D → shortlist（几十条）→ AI **只对 shortlist** 判根因+排序+写报告。同批数据同结果、上下文不爆、可审计。
7. **产出：纯 HTML 报告**（factory-ops 样式，自包含，alert box）。v1 无推送、无人工回填、无抑制。
8. **阈值（默认，可配）**：≥10× 基线 = high，3–10× = medium；C 命中（倍数 ≈ 包装规格 ± 容差）直接升 high 并标根因"包装单位错配"；D 调序。是田野"10 倍价差"的形式化。
9. **入口（默认）**：in3-mcp `execute_code`（已上线，最短路径）。

## 已知局限 / 下一步（不让它们隐形）

- **定时 + 无状态 → 噪音疲劳**（v1 主要风险）：纯无状态每期全量重报，已核验的误报每期重复出现，久了 Sourcing 弃看。**缓解后置**：轻状态（料号→首见日/复现次数/上期分值），HTML 分区 `🆕本期新增 / ♻️持续复现 / ✅本期消失`，仍纯只读、不改交付形态。**用户决定：v1 先无状态，轻状态后续再说。**
- ~~**客户端凭证续期**~~ → **已解（2026-06-25）**：改用 AGENT `client_credentials` 机器令牌，不需人、不需浏览器、无 refresh token 续期脆弱点。见下"认证突破"。
- ~~**API read-all + 价格权限**~~ → **已解（2026-06-25）**：机器令牌实测能读 MD 物料 + MM info-record，**且价格字段（unit_price/unit_tax_price）直接返回——绕过了用户级 `has_privilege:False` 价格闸**（这正是田野"没权限找人导数据"的根因）。
- **包装规格非标准字段**：`md.material` 无标准"包装规格""采购单位"字段（仅 48 个扩展字段 field_a..av，未必填）。信号 C 因此走**物料描述正则**（"250根/包"明文在描述串里），描述写法不规范的料会漏 C。
- **包装规格数值抽取是命门**：田野全表只抠出干净数值 5/3580（文本命中 1068）；扎带"250根/包"的 `根` 漏抠是它被降级的直接原因。单位词表覆盖度 = 本功能 recall 的最高杠杆，须单测专门覆盖各种"N〔单位〕/包"写法。

## Ground-truth 校准（田野《疑似PCS包装单位异常物料分析结果.xlsx》，2026-06-24）

来源：田野手导数据后用 AI 跑出的结果，3580 关联物料 / 价格记录 8564 条 / 入库明细 15403 行 / 7 条评分规则（`规则说明` sheet）。拿它当 ground truth 校准本设计，得三条硬结论：

1. **信号权重被推翻（已回写决策 #2）**：田野真实权重 = R002 描述包装规格 20 + R006 整除关系 6-19 + R004 大额入库 8-12（数量族）为主，R007 价格差异仅 3-5 当辅助。我原设计把价格离散当主触发是错的；数量模式这一族我整个漏了，已补为信号 Q。
2. **田野模型漏了引爆本项目的 case（最重要）**：扎带 **EL00556 仅 28 分 / "观察" / 优先复核=否**（排名 12）。即只看田野标"是"的 5 条会漏掉那张 10.6 万错单。根因：价差 250 倍本应强报，但他价格规则只 3-5 分；且"250根/包"漏抠数量信号也没强命中。→ **本设计必须把 P(价格离散) 提为 co-primary，并修好包装规格抽取**，才能逮住 EL00556。
3. **区分度断崖**：田野评分中位数 10、95 分位 18、到 78 是断崖；3580 条里仅 5 条建议优先复核、2 条高度疑似。因 R002/R006 大分规则受制于包装数值抽取失败（5/3580）几乎打不出来 → 中段全是 R001+R007 的 10-18 分，没区分度。修好抽取即解。

参照样本（表内实测）：
| 物料 | 田野评分/等级 | 价差倍数 | 供应商 | 最低价 | 最高价 | 互补盲区 |
|---|---|---|---|---|---|---|
| EL00505 接线端子 | 78 / 高度疑似 | 14343 | 4 | 0.033 | 473.5 | 价格+数量都逮 |
| EL00503 接线端子 | 78 / 高度疑似 | 14.5 | 3 | 0.018 | 0.257 | 都逮 |
| EL00501 接线端子 | 73 / 中度疑似 | **1.27** | 3 | 0.013 | 0.017 | **价差没逮、数量+包装逮** |
| **EL00556 扎带（本项目 case）** | **28 / 观察** | **250** | 2 | 0.057 | 14.2 | **价差应逮但被田野降权→漏** |

### 认证突破：AGENT client_credentials 机器令牌（2026-06-25 实测打通）

巡检无人值守跑批的认证用 **AGENT 服务客户端 + `client_credentials`**，不走浏览器 OAuth。实测配方（prod/indx 租户）：

```
# ① 换 token（GET，非 POST；与 password-grant 同端点）
GET https://apiv3.industics.com/service/uaas/oauth/token
    ?grant_type=client_credentials&client_id=<AGENT_ID>&client_secret=<SECRET>
  → access_token（bearer，24h），JWT claims: tenant_id=99979 / aud=[各模块] / scope=service-client

# ② 读数据（三头）
GET {host}/mom/<mod>/v2/api/tenants/99979/<entity-path>
  Authorization: Bearer <token>
  T-CODE: indx               # ★ 必须租户域名 indx，不是数字 id 99979（填 99979 会 404 x1000100）
  X-Operator-ID: <可省>      # 机器令牌无真实操作员，可空；MD/MM 读不依赖它
```

- **已验**：md.material、mm.info-record 均 HTTP 200 返数据，info-record 的 `unit_price`/`unit_tax_price` 正常返回。
- **认证路径修正（2026-06-25 复核，纠正先前误判）**：先前说"AGENT 缺 PO 权限"不准。实测对照：
  - **AGENT 机器令牌**：读 md.material + mm.info-record（含价格）OK，但 **mm.purchase-order 返 401**——其 token scope 仅 `service-client`、**无真实操作员**，PO 接口要操作员级授权，故被挡（不是缺 mm scope，aud 含 mm）。
  - **现有 indx 登录用户（password grant，有真实 operator）**：**PO 200 ✅、info-record 价格 50/50 非空 ✅**——`has_privilege:False` 只挡 UI 导出、**不挡 API**。
  - **结论**：① 用现有用户登录一个令牌即可读全（PO+价格+物料），**信号 Q 不需要任何额外权限**；② AGENT 反而更受限（无 PO），其唯一优势是 client_credentials 无人值守——但 user 登录用存储的 encrypted_password 也能无人值守自动续。→ `get_in3()` 默认走用户登录，仅显式给 AGENT 凭证时才用机器令牌。
- **网络**：测试期 apiv3 偶发 503 + SSL `UNEXPECTED_EOF`（TLS 抖动）。脚本 `_retry` 已覆盖 5xx + SSL/Connection，PO 拉取只取有包装的候选以减负。
- **关键坑**：T-CODE 用 domain 不用 id；in3_client 当前不支持 client_credentials grant，需补一段（见下一步）。
- **安全**：AGENT secret 只存凭证位置、绝不进仓库。scope 极广（全模块 + 绕价格闸），属高价值凭证。

### 有效期 + 完整 C+P+Q（2026-06-25，用户反馈后修正——关键正确性提升）

- **价格记录有效期 + 最近新建（用户两轮关键反馈）**：信号 P 的"当前价"定义 = **每供应商取其「created_date 最新且 today∈[valid_from,valid_to]」的有效记录**（`_effective_prices`），跨供应商比 max/min。
  - 已失效旧高价不算（有效期过滤）；同供应商被更新的旧记录不算（如 EL00556 e9a1c242 6-22 建了改正价 0.0568 → 其旧 14.2 排除）；
  - **但某供应商一直没改、现价仍按包错录的仍报**（用户明确要：不漏未改的供应商）。EL00556 因 29c8b6bd（管理员建、从未改）现价仍 14.2 → 仍 P0 确诊，核验要点精准点名改 29c8b6bd 那条、并指出 e9a1c242 已改到 0.0568 作正确参照。
  - 否决过的两个读法：① 只比所有记录(含已失效)→ 误报已修的 EL00554；② 每料只取全局最新一条 → 漏掉 29c8b6bd 这种未改供应商。
- **核验要点带定位**：每条标可疑记录的「当前有效·供应商·valid_from~valid_to」，Sourcing 知道改哪条
  （EL00556 精准指向 供应商29c8b6bd 仍按包错录那条，避开同料另一家已改正的 0.0568）。
- **信号 Q 全量启用**（用户登录读 PO，零额外权限）：但 Q 仅作**佐证/排序，不单独定级**——否则"高价已失效、当前定价正常、只是大批量下单"的料被 Q 误升回高危。Q 只对有包装规格的候选拉 PO（17 个，减负抗抖动）。
- **最终分组**：高度疑似 **4 条真·当前未解决**（EL00556 gold 79分 + EL00505/506/503 当前多供应商离散），P0 确诊=1(EL00556)/P1=3/P3=178 价格离散非包装。EL00554/555/501/550 等"已修/纯大批量"正确降为观察。
- **缓存**：`MDM_CACHE` 环境变量设路径=候选缓存，调权重免重拉 8564 条。
